# Архитектура и структура проекта

Этот документ описывает общую структуру и принципы организации кода проекта.

## Стек и инструменты

- React, TypeScript
- Vite (+ `@vitejs/plugin-react`, `vite-plugin-svgr`)
- Vitest (+ `@vitest/ui`, покрытие `@vitest/coverage-v8`)
- Storybook
- ESLint, Stylelint, Prettier

## Структура [WIP]

```
.
├─ public/           # статические ресурсы
├─ src/
│  ├─ assets/        # изображения, иконки, шрифты (если не public)
│  ├─ components/    # переиспользуемые UI‑компоненты
│  ├─ hooks/         # переиспользуемые React‑хуки
│  ├─ App.tsx        # корневой компонент приложения
│  ├─ main.tsx       # входная точка
│  └─ index.css      # глобальные стили (минимум)
├─ vite.config.ts    # конфигурация Vite
├─ vitest.config.ts  # конфигурация Vitest
├─ tsconfig.json     # базовая конфигурация TypeScript
└─ package.json
```

## Именование и импорт

- TypeScript: строгая типизация, избегаем `any` без необходимости.
- Компоненты: PascalCase, файлы компонентов `ComponentName.tsx`.
- SVG: импорт как React‑компонентов через `?react` (см. ниже).

### SVG

Для SVG используется [vite-plugin-svgr](https://www.npmjs.com/package/vite-plugin-svgr). Импорт в React‑коде:

```ts
import Logo from './logo.svg?react';
```

## Storybook

- Истории располагайте рядом с компонентами.
- Для наглядных UI‑изменений добавляйте скриншоты/видео в PR.

## Тестирование

- Юнит‑тесты Vitest: для утилит, хуков и компонентов с логикой.
- Цель по покрытию может регулироваться; рекомендуем ориентир 70%+.

## Стиль и форматирование

- ESLint и Stylelint проверяют код и стили.
- Prettier форматирует код единообразно.

## Производительность

- Используйте мемоизацию (`React.memo`, `useMemo`, `useCallback`) осмысленно.
- Следите за размерами бандла: `npm run build:analyze` поможет найти тяжёлые зависимости.

## Подход к архитектуре (feature-sliced, модульно‑доменный)

Проект структурирован по «слайсам» функциональности (домены/фичи) на верхнем уровне `src/` (`Auth`, `Board`, `Chat`, и др.) с единообразной внутренней слойностью и публичными API через `index.ts`.

- Вертикальная модульность по доменам:
    - Каждый слайс содержит всё, что относится к конкретной функциональности.
    - Публичные точки экспорта упорядочены через `index.ts` (в том числе в подкаталогах), чтобы изолировать внутренние детали.

- Слойность внутри слайса:
    - `components`: UI слоя фичи, часто разбит на «partials» и локальные `assets`, рядом истории Storybook и, при необходимости, тесты.
    - `hooks`: прикладные сценарии/эффекты фичи (application layer), инкапсулируют логику использования сервисов и состояния.
    - `domain`: модели предметной области, value objects (`*.attribute.ts`), типы и чистая логика.
    - `dtos`: контракты данных запросов/ответов, отделены от доменных типов.
    - `services`: доступ к данным (`*.apiClient.ts`) поверх общего HTTP‑клиента.
    - `contexts`: React‑контексты, где это оправдано.
    - `constants`, `__fixtures__`, `__handlers__`, `__tests__`: константы, фикстуры, MSW‑хэндлеры и тесты рядом с кодом.

- Общая инфраструктура:
    - В `App/services/httpClient` реализован настраиваемый HTTP‑клиент со «стратегиями» (`axiosStrategy.ts`, `fetchStrategy.ts`), билдером запросов и общими константами/типами.
    - Стили — CSS Modules; дизайн‑токены и общие стили в `App/styles`.
    - Интеграции Storybook, Vitest, MSW (фикстуры и хэндлеры на уровень фич).

- Паттерны представления:
    - Для части компонентов предусмотрены публичные варианты (`*PublicView.tsx`) под read‑only/публичные сценарии.

- Практика импортов:
    - Импортируйте преимущественно из публичных «баррелей» (`index.ts`) слайса, избегайте хождения во внутренние детали папок.

### Преимущества:

- масштабируемость (добавление фич — добавление слайсов),
- изоляция слоёв (UI/application/domain/data),
- удобство тестирования (фикстуры/handlers рядом, стратегии HTTP),
- эволюционность (стабильные публичные API через barrel‑экспорты).

### Правила зависимостей и импортов

- Внутри слайса зависимость направлена сверху вниз по слоям: UI → hooks → domain → dtos/services. Обратная направленность запрещена (например, domain не может зависеть от UI).
- Межслайсовые импорты допускаются только через публичные `index.ts` соответствующего слайса. Глубокие импорты во внутренние файлы чужих папок запрещены.
- Сетевой слой не проникает в компоненты: компоненты используют хуки; хуки — сервисы и общий HTTP‑клиент.

### Инфраструктура и тестирование

- Общий HTTP‑клиент (`App/services/httpClient`) реализует стратегии (`axiosStrategy.ts`, `fetchStrategy.ts`) и билдер запросов, централизуя политику таймаутов/ошибок и упрощая тестирование.
- MSW: у фич предусмотрены `__fixtures__` и `__handlers__` рядом с кодом для автономной разработки и юнит‑тестов.
- Storybook: истории располагаются рядом с компонентами для визуальной регрессии и удобной коммуникации в PR.

### Рекомендации по добавлению фич

- Новый функционал оформляйте отдельным слайсом верхнего уровня в `src/`.
- Внутри слайса поддерживайте слойность: `domain`, `dtos`, `services`, `hooks`, `components` (+ `contexts`, `constants` при необходимости).
- Экспортируйте публичные сущности слайса через его `index.ts` и аналогичные `index.ts` в подпапках.

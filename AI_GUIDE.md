# Инструкции для ИИ‑агентов

Этот файл помогает ИИ‑ассистентам эффективно работать с кодовой базой проекта.

## Цели и контекст

- Репозиторий — проект на Vite + React + TypeScript с настроенными линтерами, тестами и Storybook.
- Основная задача — ускорять создание фронтенд‑приложений по единому стандарту качества.

## Ограничения и договорённости

- Поддерживаем Node.js 18+.
- Следуем [CODE_OF_CONDUCT.md](./CODE_OF_CONDUCT.md) и [ARCHITECTURE.md](./ARCHITECTURE.md).
- Все изменения должны соответствовать линтерам и проходить тесты.

## Как принимать решения

1. Отталкивайтесь от текущих скриптов из `package.json` (не выдумывайте несущ. команды).
2. Сначала читайте `README.md`, `CODE_OF_CONDUCT.md`, `ARCHITECTURE.md`, затем исходники в `src/`.
3. Предлагайте минимально достаточные изменения, избегайте бессмысленных крупных рефакторингов.
4. Обязательно учитывайте версии зависимостей и их совместимость.

## Типичный рабочий процесс

1. Установка и запуск:
    - `npm install`
    - `npm run dev`
2. Качество:
    - `npm run eslint:check`
    - `npm run stylelint:check`
    - `npm run prettier:check`
    - `npm run test` / `npm run test:coverage`
3. Сборка и анализ:
    - `npm run build`
    - `npm run build:analyze`

## Рекомендации по коду

- Пишите ясный, многословный код: понятные имена переменных и функций.
- Используйте ранние возвраты, избегайте глубокой вложенности.
- Комментарии — только там, где необходимы для понимания (не очевидные решения/инварианты).
- Для React: разумно применяйте мемоизацию, избегайте «лишних» ререндеров.

## Документация PR

- Формируйте осмысленное описание изменений, влияние на UX/перфоманс, риски.
- По возможности прикладывайте скриншоты/видео UI‑изменений и список команд для проверки.

## Когда спрашивать человека

- Неочевидные продуктовые решения, конфликтующие требования.
- Изменения в процессах CI/CD, секреты/конфигурации окружений.
- Сомнения в архитектурном выборе, влияющие на долгосрочное обслуживание.

## Общие правила работы

- Все ответы, артефакты и комментарии в репозитории оформляй на русском языке.
- Сначала прочитай `README.md`, `CODE_OF_CONDUCT.md`, `ARCHITECTURE.md`, релевантные `.agents/skills/*/SKILL.md`, затем исходники в `src/`.
- Используй существующие скрипты из `package.json`; не придумывай несуществующие команды.
- Предлагай и вноси минимально достаточные изменения, переиспользуя существующие решения проекта.
- Подчищай устаревший и ненужный код, если это безопасно в рамках задачи.
- Учитывай версии зависимостей и совместимость текущего стека.
- Если в продуктовый проект добавлены внутренние UI-библиотеки, утилиты или company packages, сначала проверь их перед написанием нового решения.

## Проверки после изменений

- После правок кода запускай релевантные проверки:
    - `npm run eslint:check`
    - `npm run typescript:check`
    - `npm run test:check`
    - `npm run stylelint:check`
    - `npm run prettier:check`
- Ресурсоёмкие проверки запускай последовательно.
- Для документационных правок достаточно проверить форматирование затронутых файлов или объяснить, почему полная проверка не запускалась.

## Канонические инструкции проекта

- Общие AI-инструкции живут только в `AGENTS.md`.
- `CLAUDE.md` — тонкий entrypoint для Claude Code, который импортирует `AGENTS.md` и не дублирует общие правила.
- Канонические skills живут только в `.agents/skills/*/SKILL.md`.
- При изменениях документации, skills или MCP-конфигурации следуй `.agents/skills/documentation-update/SKILL.md`.
- Для архитектуры, компонентов, типизации, тестов, стилизации, нейминга, производительности, Storybook, ревью, pull/merge request и исправления замечаний из request читай соответствующие skills из `.agents/skills/`.

## MCP и IDE-слой

- Для Codex канонический repo-level MCP-конфиг находится в `.codex/config.toml`. Codex читает его только в trusted project.
- Для Cursor используется `.cursor/mcp.json`.
- Для Claude Code desktop MCP настраивается во внешнем конфиге приложения или через Connectors.
- Не дублируй общие проектные инструкции в MCP-конфигах IDE: они описывают только transport/config layer.

## Когда спрашивать человека

- Если нужно принять неочевидное продуктовое решение или есть конфликт требований.
- Если изменения затрагивают CI/CD, секреты или конфигурацию окружений.
- Если архитектурный выбор заметно влияет на долгосрочное сопровождение и есть несколько равноправных вариантов.
- Если для задачи нужны внешние референсы, макеты или доступы, которых нет в репозитории.

# React-компоненты

## Перед началом

- Проверь существующие компоненты в `src/components/` или выбранном shared-слое проекта.
- Если продуктовый проект подключил UI-библиотеку, сначала проверь её возможности.
- Не добавляй новую UI-абстракцию, если задача решается простым компонентом и повторное использование не доказано.

## Библиотека общих компонентов

## Рекомендации по компонентам

1. Один компонент — один файл и одна ответственность.
2. Используй ранние возвраты и минимальную вложенность.
3. Не используй `data-testid`, если элемент можно выбрать по роли, имени, label или тексту.
4. Для опциональных пропсов задавай понятные значения по умолчанию. Булевые пропсы по умолчанию `false` и типизируются как опциональные.
5. Наследуйся от нативных HTML-атрибутов, где это уместно: `interface IInputProps extends InputHTMLAttributes<HTMLInputElement> {}`.
6. Компонент содержит только логику представления. Получение данных, API и глобальное состояние выноси в хуки или контейнеры.
7. Один `useEffect` — один сайд-эффект.
8. Локальное состояние компонента — только для UI-логики.
9. JSX должен быть читаемым: сложную логику выноси в переменные, функции и коллбеки. Обработчики именуй `handle*`.
10. Используй `children` для содержимого, когда компонент естественно оборачивает другой UI.
11. Каждая обёртка в разметке должна иметь семантическую, стилевую или ARIA-нагрузку.
12. Небольшие компоненты фичи можно оставить в месте применения, если вынос не улучшает читаемость.

## Экспорты

- React-компоненты можно экспортировать `default`, если это соответствует стилю проекта.
- Типы, функции, хуки и константы экспортируй именованно.
- Публичные сущности экспортируй через `index.ts`, только если они действительно используются снаружи.

## Доступность

- Используй семантическую разметку (`section`, `article`, `nav`, `button`, `a`) где уместно.
- Для интерактивных элементов без видимого текста добавляй `aria-label`.
- Неинтерактивные элементы с `onClick` избегай; если без них нельзя, добавь `role="button"` и клавиатурную поддержку.
- Сообщения об ошибках помечай `role="alert"`.
- Для композиции ссылки и визуальной кнопки интерактивным элементом остаётся ссылка.

```tsx
<a href={href} className={buttonClassName}>
    Подробнее
</a>
```

## Контексты

- Экспортируй только провайдер и хук доступа к контексту.
- Если контекст содержит часто меняющееся состояние и стабильные методы, разделяй state и actions или мемоизируй значение провайдера.

## Рекомендации по хукам

Если хуку нужна DOM-нода, принимай `ref` параметром, чтобы вызывающий код мог управлять ссылкой снаружи.

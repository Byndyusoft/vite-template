# Чек-лист ревью кода

При ревью проверяй изменённые строки и ближайший контекст. Нарушение формулируй конкретно: файл, строка, риск и способ исправления.

## 1. Оформление PR

- [ ] Есть осмысленное описание: цель, контекст, изменения.
- [ ] Указаны breaking changes, если они есть.
- [ ] Для UI-изменений приложены скриншоты или видео.
- [ ] PR тематически целостный и не смешивает независимые задачи.
- [ ] Чек-лист PR заполнен.
- [ ] При автоматическом создании, ревью или исправлении замечаний request соблюдены правила [create-pull-request](../create-pull-request/SKILL.md), [review-pull-request](../review-pull-request/SKILL.md) и [refactor-pull-request](../refactor-pull-request/SKILL.md).

## 2. Архитектура

- [ ] Новая фича следует выбранной структуре проекта.
- [ ] Общий код вынесен только при реальном повторном использовании.
- [ ] Публичный API экспортируется через `index.ts`, если сущность используется снаружи.
- [ ] Доменная логика не зависит от React, UI и сетевого слоя.
- [ ] Сервисы не вызываются напрямую из компонентов.
- [ ] Файлы не разрастаются сверх разумного размера.
- [ ] Не добавлены крупные архитектурные изменения без необходимости.

## 3. Типизация

- [ ] Строгий TypeScript сохранён.
- [ ] Нет необоснованного `any`.
- [ ] `type` и `interface` именуются по соглашению `T*` и `I*`.
- [ ] Публичные функции, хуки и компоненты типизированы явно.
- [ ] Нет крупных инлайновых типов в параметрах.
- [ ] Новые env-переменные добавлены в `ImportMetaEnv` и документацию.

## 4. Именование

- [ ] Используются `camelCase`, `PascalCase`, `UPPER_SNAKE_CASE` по назначению.
- [ ] Предикаты начинаются с `is`, `has`, `can`, `should`.
- [ ] Колбеки в пропсах именуются `on*`, внутренние обработчики — `handle*`.
- [ ] Нет неочевидных сокращений.
- [ ] Имена файлов соответствуют роли сущности.

## 5. Компоненты

- [ ] Компонент имеет одну ответственность.
- [ ] JSX читаемый, сложная логика вынесена в переменные или функции.
- [ ] Состояние компонента относится к UI-логике.
- [ ] Один `useEffect` отвечает за один сайд-эффект.
- [ ] Нет лишних обёрток без семантической или стилевой нагрузки.
- [ ] Переиспользуемые компоненты проекта не продублированы кастомной реализацией.

## 6. Стили

- [ ] Стили компонента расположены рядом с компонентом или по принятому соглашению проекта.
- [ ] Нет inline-стилей без необходимости.
- [ ] Повторяющиеся цвета, отступы и размеры вынесены в токены, если такие токены уже используются.
- [ ] Адаптив проверен на поддерживаемых ширинах.
- [ ] Focus-состояния не сломаны.

## 7. Экспорт и импорт

- [ ] Импорты идут из актуальных мест.
- [ ] Нет legacy-реэкспортов после переноса сущностей.
- [ ] Нет неиспользуемых экспортов.
- [ ] Подход к относительным импортам или aliases соответствует проекту.

## 8. Тестирование

- [ ] Новая или изменённая сложная логика покрыта тестами.
- [ ] Тесты проверяют пользовательское поведение, а не детали реализации.
- [ ] Покрыты важные негативные и граничные сценарии.
- [ ] Моки и фикстуры переиспользуются, если в проекте есть такая инфраструктура.
- [ ] Тесты не пропущены без причины.

## 9. Storybook

- [ ] Для новых или изменённых UI-компонентов есть stories, если компонент должен демонстрироваться отдельно.
- [ ] Stories показывают основные состояния: default, loading, empty, error, disabled, если они применимы.
- [ ] `args` и controls используются для публичных пропсов.

## 10. Полнота реализации

- [ ] Все требования задачи реализованы.
- [ ] Нет TODO/FIXME/HACK без понятного контекста или ссылки на задачу.
- [ ] Обработаны состояния загрузки, ошибки, пустого результата и успеха, если они применимы.
- [ ] Тексты соответствуют задаче и не содержат случайный placeholder.

## 11. Производительность

- [ ] `useCallback`, `useMemo` и `memo` используются только там, где есть смысл.
- [ ] Состояние расположено близко к месту использования.
- [ ] Нет тяжёлых вычислений на каждый рендер без необходимости.
- [ ] Нет лишних сетевых запросов из-за нестабильных зависимостей.

## 12. Доступность

- [ ] Интерактивные элементы доступны с клавиатуры.
- [ ] Элементы без видимого текста имеют доступное имя.
- [ ] Сообщения об ошибках доступны скринридерам.
- [ ] Семантическая разметка используется там, где она уместна.

## 13. Кроссбраузерность

- [ ] CSS и JS API поддерживаются целевыми браузерами.
- [ ] Для неоднозначных CSS-свойств есть fallback или проверенная поддержка.
- [ ] UI проверен на целевых ширинах проекта.

## 14. Безопасность

- [ ] В коде и документации нет секретов.
- [ ] `dangerouslySetInnerHTML` не используется без санитизации.
- [ ] Внешние ссылки и URL обрабатываются безопасно.

## 15. Линтеры и сборка

- [ ] `npm run eslint:check` проходит.
- [ ] `npm run stylelint:check` проходит.
- [ ] `npm run prettier:check` проходит.
- [ ] `npm run typescript:check` проходит.
- [ ] `npm run test:check` проходит.
- [ ] `npm run build` проходит, если изменения затрагивают runtime-код или конфигурацию сборки.

## 16. Документация

- [ ] Документация обновлена по [documentation-update](../documentation-update/SKILL.md).
- [ ] `AGENTS.md` остаётся единым источником общих AI-инструкций.
- [ ] IDE/MCP-конфиги не дублируют правила проекта.
- [ ] В шаблон не добавлены проектно-специфичные инструкции, платформенные workflow или доменные правила без отдельного решения.

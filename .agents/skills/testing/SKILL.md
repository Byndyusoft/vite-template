# Тестирование

## Стек тестирования

- Базовый test runner — Vitest.
- Используй существующую тестовую инфраструктуру проекта и скрипты из `package.json`.
- Не добавляй новые тестовые библиотеки без явной необходимости. Если для компонентных тестов нужна Testing Library или MSW, сначала проверь, подключены ли они уже.

## Структура теста

Тесты группируй через `describe`. Внутри каждого теста держи структуру arrange / act / assert.

```ts
describe('formatName', () => {
    test('возвращает полное имя', () => {
        // arrange
        const firstName = 'Анна';
        const lastName = 'Иванова';

        // act
        const result = formatName(firstName, lastName);

        // assert
        expect(result).toBe('Анна Иванова');
    });
});
```

## Паттерн setup

Для повторяющейся подготовки сцены используй функцию `setup()`.

```tsx
function setup(props: Partial<IComponentProps> = {}) {
    return render(<Component {...defaultProps} {...props} />);
}
```

## Приоритет UI-селекторов

Если проект использует Testing Library, выбирай элементы в таком порядке:

1. `getByRole`
2. `getByLabelText`
3. `getByText`
4. `getByPlaceholderText`

Избегай `getByTestId` и `data-testid`, если элемент можно выбрать по доступному имени или роли.

## Симуляция действий

Если подключён `@testing-library/user-event`, предпочитай его `fireEvent`.

```ts
await userEvent.click(screen.getByRole('button', { name: 'Сохранить' }));
```

## Моки HTTP

- Если проект использует MSW, храни фикстуры в `__fixtures__/`, хэндлеры в `__handlers__/` и переиспользуй их в тестах и Storybook.
- Если MSW не подключён, не добавляй его автоматически: оцени масштаб задачи и существующие паттерны.

## Что покрывать

1. Чистую доменную логику и утилиты.
2. Хуки со значимой логикой.
3. Компоненты с ветвлениями, состояниями и пользовательскими действиями.
4. Сценарии багов.
5. Адаптеры DTO, если формат данных преобразуется.

Ориентир покрытия — около 70%, но приоритетнее закрыть критические сценарии.

## Конфигурация Vitest

- Не пропускай тесты в CI без отдельной причины.
- Используй `vi` из Vitest для моков.
- Не смешивай Jest API и Vitest API.
